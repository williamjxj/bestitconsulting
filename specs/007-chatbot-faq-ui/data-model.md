# Data Model: Chatbot CSS Improvements and FAQ Integration

## Overview
This feature primarily involves UI/CSS changes with minimal data structure modifications. This document outlines the data structures involved in the implementation.

## Data Structures

### 1. FAQ Item Structure

**Source:** Used in AnimatedFAQ component and contact page

```typescript
interface FAQItem {
  /**
   * Unique identifier for the FAQ item
   * Used for React keys and tracking which items are expanded
   */
  id: string

  /**
   * The question text displayed to users
   * Should be translated via i18n system
   */
  question: string

  /**
   * The answer text displayed when FAQ item is expanded
   * Should be translated via i18n system
   */
  answer: string
}
```

**Example:**
```typescript
const faqItem: FAQItem = {
  id: 'timeline',
  question: 'What is your typical project timeline?',
  answer: 'Depends on the project requirements and details.'
}
```

**Validation Rules:**
- `id`: Required, unique within FAQ array, kebab-case recommended
- `question`: Required, non-empty string, 10-200 characters
- `answer`: Required, non-empty string, 50-1000 characters

**State Management:**
- FAQ expanded/collapsed state managed in AnimatedFAQ component
- Uses Set<string> to track expanded item IDs
- Persisted in component state only (not localStorage)

### 2. Chat Message Structure

**Source:** Existing in chat-widget-panel.tsx (no changes to structure)

```typescript
interface Message {
  /**
   * Unique identifier for the message
   * Generated by Vercel AI SDK
   */
  id: string

  /**
   * Role of the message sender
   * 'user' for human messages, 'assistant' for AI responses
   */
  role: 'user' | 'assistant' | 'system'

  /**
   * Text content of the message
   * Used for backward compatibility
   */
  content: string

  /**
   * Timestamp when message was created
   * Used for displaying message time
   */
  timestamp: number

  /**
   * Optional message parts for structured content
   * Used by Vercel AI SDK for streaming
   */
  parts?: Array<{
    type: 'text'
    text: string
  }>
}
```

**Example:**
```typescript
const userMessage: Message = {
  id: 'msg_abc123',
  role: 'user',
  content: 'What services do you offer?',
  timestamp: 1706268000000,
  parts: [
    {
      type: 'text',
      text: 'What services do you offer?'
    }
  ]
}

const assistantMessage: Message = {
  id: 'msg_def456',
  role: 'assistant',
  content: 'We offer web development, mobile apps, cloud solutions...',
  timestamp: 1706268005000,
  parts: [
    {
      type: 'text',
      text: 'We offer web development, mobile apps, cloud solutions...'
    }
  ]
}
```

**Validation Rules:**
- `id`: Required, unique, generated by AI SDK
- `role`: Required, must be 'user', 'assistant', or 'system'
- `content`: Required, non-empty string
- `timestamp`: Required, Unix timestamp in milliseconds
- `parts`: Optional, array of text parts

**State Management:**
- Messages managed by Vercel AI SDK useChat hook
- Synced to localStorage via useChatWidget hook
- Persisted across sessions for conversation history

### 3. Translation Key Structure

**Source:** i18n translation files (en.ts, es.ts, fr.ts, zh.ts)

```typescript
interface ContactTranslations {
  contact: {
    faq: {
      /**
       * Section title for FAQ on contact page
       */
      sectionTitle: string

      /**
       * Section description/subtitle
       */
      sectionDescription: string

      /**
       * Individual FAQ items
       * Each FAQ has a question and answer key
       */
      [key: string]: {
        question: string
        answer: string
      } | string
    }
  }
}
```

**Example:**
```typescript
// English translations (en.ts)
const translations = {
  contact: {
    faq: {
      sectionTitle: "Frequently Asked Questions",
      sectionDescription: "Find answers before you reach out",
      timeline: {
        question: "What is your typical project timeline?",
        answer: "Depends on the project requirements and details."
      },
      support: {
        question: "Do you offer ongoing support and maintenance?",
        answer: "Yes, we provide comprehensive support packages..."
      }
    }
  }
}

// Spanish translations (es.ts)
const translations = {
  contact: {
    faq: {
      sectionTitle: "Preguntas Frecuentes",
      sectionDescription: "Encuentra respuestas antes de contactarnos",
      timeline: {
        question: "¿Cuál es su cronograma típico de proyecto?",
        answer: "Depende de los requisitos y detalles del proyecto."
      }
      // ... more translations
    }
  }
}
```

**Validation Rules:**
- All translation keys must exist in all language files
- Strings should be non-empty
- Maintain consistent structure across languages
- Use proper UTF-8 encoding for special characters

**State Management:**
- Loaded at application start
- Cached in memory
- Updated via useI18n hook
- No persistence needed (loaded fresh each session)

## Component State

### AnimatedFAQ Component State

```typescript
interface AnimatedFAQState {
  /**
   * Set of FAQ item IDs that are currently expanded
   * Empty set means all items are collapsed
   */
  openItems: Set<string>
}
```

**State Transitions:**
```
Initial: openItems = Set()

User clicks FAQ item:
  - If item.id NOT in openItems:
      openItems.add(item.id) → Item expands
  - If item.id IN openItems:
      openItems.delete(item.id) → Item collapses

Multiple items can be open simultaneously
```

**Example:**
```typescript
// Initial state - all collapsed
openItems = Set()

// User expands "timeline" FAQ
openItems = Set(['timeline'])

// User expands "support" FAQ (both now open)
openItems = Set(['timeline', 'support'])

// User collapses "timeline" FAQ
openItems = Set(['support'])
```

### ChatWidgetPanel Component State

```typescript
interface ChatWidgetPanelState {
  /**
   * Current input text in the message input field
   */
  input: string

  /**
   * ID of message that was just copied (for showing "copied" indicator)
   */
  copiedMessageId: string | null

  /**
   * Whether initialization is complete
   * Prevents duplicate message loading from localStorage
   */
  isInitialized: boolean
}
```

**State Transitions:**
```
Initial: 
  input = ''
  copiedMessageId = null
  isInitialized = false

User types message:
  input = 'Hello' → Updates as user types

User submits message:
  input = '' → Cleared after submission

User copies message:
  copiedMessageId = 'msg_abc123' → Shows checkmark
  After 2 seconds: copiedMessageId = null → Back to copy icon

Initialization:
  isInitialized = false → Loads messages from localStorage
  isInitialized = true → Prevents re-loading
```

## Data Flow

### FAQ Integration Data Flow

```
1. Page Load (app/contact/page.tsx)
   ↓
2. Define FAQ data array with i18n keys
   const contactFaqs = [
     { id: 'timeline', question: t('faq.timeline.question'), ... }
   ]
   ↓
3. Pass to AnimatedFAQ component
   <AnimatedFAQ faqs={contactFaqs} />
   ↓
4. Component renders FAQ items
   - Each item as collapsible Card
   - Click toggles openItems Set
   ↓
5. Framer Motion animates expansion/collapse
   - Height animation
   - Opacity fade
   - Respects reduced motion preference
```

### Chatbot Message Data Flow

```
1. User types message
   ↓
2. handleSubmit called
   ↓
3. sendMessage from useChat hook
   ↓
4. POST to /api/chat endpoint
   ↓
5. AI SDK streams response
   ↓
6. Messages array updated
   ↓
7. useEffect syncs to localStorage
   ↓
8. Component re-renders with new message
   ↓
9. Auto-scroll to bottom
```

## Storage

### localStorage Schema

**Key:** `chat-widget-messages`

**Value:** JSON array of Message objects

```typescript
// Stored in localStorage
{
  "chat-widget-messages": [
    {
      "id": "msg_abc123",
      "role": "user",
      "content": "Hello",
      "timestamp": 1706268000000,
      "parts": [{ "type": "text", "text": "Hello" }]
    },
    {
      "id": "msg_def456",
      "role": "assistant",
      "content": "Hi! How can I help?",
      "timestamp": 1706268005000,
      "parts": [{ "type": "text", "text": "Hi! How can I help?" }]
    }
  ]
}
```

**Size Limit:** 5MB per origin (localStorage limit)

**Persistence:** Persists across sessions until manually cleared

**Privacy:** Client-side only, not sent to server

## Summary

### Key Data Structures
1. **FAQItem**: Question/answer pairs for FAQ component
2. **Message**: Chat messages with role, content, timestamp
3. **Translation Keys**: i18n strings for multi-language support

### State Management
- **FAQ State**: Set of expanded item IDs (component state)
- **Chat State**: Message array (useChat hook + localStorage)
- **Translations**: Loaded at app start, cached in memory

### Storage
- **localStorage**: Chat message persistence only
- **No database**: Pure frontend feature
- **No API changes**: Existing endpoints unchanged

### Data Flow
- FAQ: Static data → Component → User interaction
- Chat: User input → API → Streaming response → localStorage

This feature has minimal data modeling requirements since it primarily involves UI/CSS changes with existing data structures.
